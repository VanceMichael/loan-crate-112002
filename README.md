# 巡展箱开封作业与馆方接收取证的演练来源

这里提供独立来源的本地合成记录，与实际单位、个人和线上业务无关。

## 本地运行

使用 Node.js 22.23.4。只使用 Node.js 自带的运行库。

执行 `npm test` 检查合成来源的接口。执行 `npm start` 启动来源，默认监听 `127.0.0.1:4100`，可通过环境变量 `PORT` 调整端口。访问根路径可看到来源名和当前回放阶段。

## 接口资料

| GET 路由 | 来源约定 |
| --- | --- |
| `/source/carrier` | caseSeal 标识一次封箱。parent 为被换的封条，mode 为换外箱或重新分装。版本号码按场次递增。 |
| `/source/origin` | 作品以 workId 标识。scope 为能执行的操作。closedTransfer 允许搬运封闭内盒。 |
| `/source/vault` | receipt 声明当时的物理动作，照片编号只可作为相应实物凭据。 |

查询参数 `offset` 是从零开始的页偏移，`limit` 默认 3，取值 1 至 100。响应中的 `records` 含 `record` 来源记录键、`availableFrom` 首次出现的回放阶段、`kind` 记录类型、`payload` 业务字段。来源记录键与业务身份分别定义。`next` 为下一页偏移，末页为 `null`。回放阶段中的记录按到达顺序可查。

控制员通过 `POST /control?stage=2` 切换到第 2 阶段，服务会保留更早已可查的记录。每次换阶段后按根路径返回的 `stage` 确认切换成功。

库房的 slot 给出当前可排的时段和实际经办人。presence 是出借方到场授权，以 permit、封条、清单版、部件和操作为准。open 的 outer 与 inner 分别记录外层和内层现场动作，关联合适的现场凭据。sealed 记录当地负责保管的人员。

现场授权包含场次、封条、分装版次、物件清单及操作。slot 给出当值人和可用窗口，open 分别记外箱、内盒状态，sealed 是当场保管人员签收。

## 交接账本

在来源之上运行 `loadHandover`，把三处来源采集、归并后给出箱级和作品级视图：

```js
import { loadHandover } from './handover.mjs';

const handover = await loadHandover({ url: 'http://127.0.0.1:4100' });
handover.crates();                                   // 当前仍有效的箱号（已被换掉的箱不再列出）
handover.crate('SE05', { site: '谷馆' });            // 按箱看每件在本站能做什么、卡在哪
handover.work('W-J', { site: '谷馆' });              // 按作品看齐套缺失、从哪一代起无法证明
handover.readiness('W-J', { site: '谷馆' });         // 这件作品能否交给布展
handover.slot('SE05', { site: '谷馆', at: '12:05' }); // 排期前的闸门
handover.handoffPlan('SE05', { site: '谷馆' });      // 交接同事的作业单
```

分层：

| 文件 | 职责 |
| --- | --- |
| `collect.mjs` | 按阶段翻页采集，记录首次出现的阶段；同一 `record` 重复到达时要求内容一致。 |
| `ledger.mjs` | 结构校验、封条版本链解析、按时间排序。换箱记录表示上一代封条已断开，旧箱不再作为当前箱。 |
| `evaluate.mjs` | 许可范围、开封与点验是否可用、可证明性、作品交付与排期闸门。 |
| `handover.mjs` | 对外入口，把采集与裁决组合成按箱/按作品的交接视图。 |

## 判定口径

- **三条轴互相独立**：物证（到站、封条、开封、封存）、许可（部件 × 场馆 × 操作）、可证明性（每一代换箱都有与清单版本一致的签收）。任一条不成立，该件都不算“已经查齐”。
- **箱号不等于作品部件**：一件展品可以拆进两只箱，一只箱也可能装几件展品的支架。按箱看的是当前这一代封条下的内容，按作品看的是必要部件是否都能落到有效点验。
- **换外箱与重新分装**：换外箱不改变内容，原内盒映射原样带过来，改内容记为账本问题；重新分装按新清单处理，必须交清单，并按封闭内盒状况交代原内盒件的去向。
- **时间用业务时间**：分箱更正晚到不会回填历史。谷馆在 11:40 重新分装后 12:10 当面点验 K1，这次点验仍然成立；但账上仍会标出 SE05 这一代从 11:40 起没有签收。
- **同箱暴露**：只获准点验其中一件时，若开箱会暴露未获准点验的其他件，整箱开封请求挂起并给出缘由。出借方允许封闭内盒原样周转的件不算暴露，但点验状态仍记为未知。
- **已领用许可的边界**：许可写明封条或清单版本时，只对那一代有效；许可到期或被撤销后，之后的操作不再获准，撤销点之前已发生的事实不追溯改写。
- **排期闸门**：封条核对失败或换箱之后，旧箱不再排期；已开箱的箱要核对当时是否获准、谁接手封存，不能当成还没开过。
- **作品交付**：只有必要部件都能在本站关联到有效点验、且对应安装许可仍有效时，才把作品交给布展；被挂起的部件不阻挡其他持有独立有效凭据的作品。
